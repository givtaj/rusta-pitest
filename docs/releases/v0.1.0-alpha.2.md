# v0.1.0-alpha.2

First public alpha of rusta-pitest, a Rust CLI for HTTP API checks and
benchmarks. Release date: October 26, 2026.

## Included

- GET and POST requests with optional JSON bodies.
- Request-count and duration workloads, concurrency, full-response timeouts,
  exact expected-status checks, and explicit failure exit codes.
- A guided wizard, optional Roots request catalogue, and four-endpoint SleepAPI
  profile with optional simulation contract validation.
- Terminal summaries and schema-versioned JSON reports with request accounting,
  throughput, approximate latency quantiles, and build identity.
- Existing-file protection and omission of credentials, query strings,
  fragments, and request bodies from saved request metadata.
- Standalone public documentation, contribution instructions, and private
  vulnerability reporting.
- Per-target third-party license notices included in release archives.

## Supported artifacts

Linux x86_64 (Ubuntu 24.04 or a compatible glibc environment) and macOS arm64.
Each binary archive includes the Apache 2.0 license, README, third-party notices,
checksums, and build metadata. The release also provides `SHA256SUMS` for the
archives. macOS binaries are unsigned and not notarized. See
[installation](../../README.md#install-the-alpha).

## Validation record

The [release policy](../release-policy.md) requires the Rust and Python suites,
formatting, Clippy, release-binary smoke checks, notice-generation checks, and
`cargo-audit` 0.22.2 with `cargo audit --deny warnings` to pass. The dependency
threshold is zero known vulnerabilities and zero denied warnings.

The [published GitHub release](https://github.com/givtaj/rusta-pitest/releases/tag/v0.1.0-alpha.2)
is the authoritative record of the final commit, passing CI and artifact-build
runs, test counts, archive names, and checksum verification. All evidence must
refer to this public release's exact source revision.

## Known limitations

- Alpha CLI and JSON interfaces may change. No general performance or
  production-readiness guarantee is made.
- Load is closed-loop: slower responses reduce the generated request rate.
  There is no constant-arrival-rate scheduler, warmup, distributed execution,
  or configurable latency/throughput pass threshold.
- Requests use HTTP/1.1. Redirects, retries, and environment proxies are disabled.
  Custom headers and session cookies are not supported.
- Histograms aggregate latency with three significant digits; percentile values
  are approximate. Small samples are smoke checks.
- Start at concurrency 1–4 and increase cautiously. No maximum safe concurrency
  or capacity has been verified for the runner or target service.
- Duration runs finish in-flight responses under the request timeout, so total
  elapsed time can exceed the requested window.
- Interrupted runs do not produce completed reports. Saved URL paths remain
  visible; avoid embedding sensitive data in paths before sharing reports.
- Optional target services must already be running. Presets depend on their
  route and response contracts; the runner does not deploy or manage them.
- Windows, Intel macOS, Linux arm64, and older glibc environments are unverified.
- Builds from source archives without Git metadata report unknown Git revision
  and source cleanliness (`null` in JSON). Official binaries carry the tagged
  source revision and clean source marker.

This alpha is distributed through GitHub. No crates.io publication is included.
