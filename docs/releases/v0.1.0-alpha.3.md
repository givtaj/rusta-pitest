# v0.1.0-alpha.3

Experimental OpenAPI contract suites for rusta-pitest. Release date: October 26,
2026. Existing benchmark commands and their version-1 reports remain supported.

## Included

- Generate a deterministic, reviewable suite from raw OpenAPI 3.1.0–3.1.2 JSON
  or YAML supplied as an HTTP(S) URL or local filesystem path.
- Freeze contract inputs and record source, contract, and suite hashes. No
  operation requests or external-reference downloads occur during generation.
- Preview cases, missing bindings, unsupported semantics, and blocked writes
  without operation traffic or reading credential values.
- Explicitly execute selected GET/HEAD operations against a configured target,
  with required resource fixtures and bearer/header API-key environment bindings.
- Check documented success status, supported JSON media types and syntax,
  supported response headers, and the declared JSON Schema constraints.
- Use one request per operation, sequential execution, request budgets, rate
  pacing, full-response timeouts, bounded capture, and exclusive output creation.
- Save separate suite reports with per-case coverage and build provenance,
  excluding target URLs, runtime credentials, fixtures, and response payloads.

See the [OpenAPI guide](../openapi-suites.md) and
[synthetic example](../../examples/widgets.openapi.yaml).

## Supported artifacts and verification

Linux x86_64 (Ubuntu 24.04 or a compatible glibc environment) and macOS arm64.
Archives contain the executable, README, Apache 2.0 license, target-specific
third-party notices and Rust standard-library attribution, internal checksums,
and build provenance. macOS binaries are unsigned and not notarized. No
crates.io publication is included.

The [release policy](../release-policy.md) requires all discovered Rust and
Python tests, formatting, Clippy, dependency audits, verified notices, and
built/extracted binary smoke checks on both supported platforms. The dependency
threshold is zero known vulnerabilities and zero denied warnings. New acceptance
cases cover authentication alternatives/combinations, header conflicts, request
budgets, rate pacing, full-body timeouts, and response-size boundaries.

The [published GitHub release](https://github.com/givtaj/rusta-pitest/releases/tag/v0.1.0-alpha.3)
records the exact public source revision, passing CI/artifact runs, observed
test counts, archive names, and verified SHA-256 digests.

## Known limitations

- This is a supported subset of OpenAPI 3.1. OpenAPI 2.0, 3.0 and 3.2, external
  references, schema identifiers/anchors and dynamic references are unsupported.
- Writes remain visible but cannot execute. Setup/cleanup, operation dependency
  orchestration, callbacks/webhooks, OAuth acquisition, cookie/session flows,
  multipart/binary requests, and negative/property-based testing are deferred.
- Parameter serialization supports scalar path/header values and scalar/array
  query values with the documented simple/form styles. Other serializers block
  the affected case. Response media support is JSON and bodyless responses.
- `format`, `readOnly`, `writeOnly`, and content annotations are not extra
  assertions. Unsupported schemas block cases. Candidate synthesis is narrower
  than response validation and may require a simpler schema or reviewed binding.
- Fixture IDs must identify resources in the selected test environment; a valid
  schema or example does not establish business semantics or resource existence.
  A 202 response checks the immediate contract, not eventual completion.
- A passing selection is not a complete-contract pass. Skipped/blocked cases
  remain in coverage totals, and absent response schemas are reported explicitly.
- Suites include frozen imported documentation/examples. Review their contents
  before sharing. Runtime credentials are supplied separately; contract-provided
  operation IDs remain visible in reports.
- Existing benchmark limitations still apply: closed-loop load, approximate
  latency quantiles, no universal capacity guarantee or latency/throughput gates.
  Windows, Intel macOS, Linux arm64, and older glibc systems are unverified.
- CLI and report interfaces remain alpha. Interrupted processes do not publish
  complete reports. Source archives without Git metadata report unknown source
  identity; official binaries must carry the exact clean tagged revision.
