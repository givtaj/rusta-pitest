# v0.1.0-alpha.6

Private cookie authentication for generated OpenAPI suites and structured query
parameters for authored workloads. Prepared release date: November 17, 2026.
CLI and report interfaces remain alpha.

## Included

- Bind declared OpenAPI `apiKey` security schemes with `in: cookie` through
  `--auth-env scheme=VARIABLE`. The contract supplies the cookie name; the
  environment supplies only its opaque value.
- Validate cookie names and values before traffic, reject conflicting bindings,
  and construct combined cookies deterministically while preserving security
  alternatives and combinations. Preview does not resolve credentials.
- Supply bounded, ordered literal `query` name/value pairs in authored requests,
  preserving repeated names and empty values with exact UTF-8 percent encoding.
- Reject malformed or oversized queries before setup or measured traffic.
  Query data and runtime authentication values remain absent from runner reports
  and diagnostics.
- Exercise both capabilities through built and extracted release executables,
  including isolated synthetic users, denied positive assertions, missing or
  malformed credentials, exact query bytes, preflight rejection and redaction.

See [private cookie bindings](../openapi-suites.md#private-cookie-bindings),
[structured query parameters](../workloads.md#structured-query-parameters), and
the [complete synthetic query example](../../examples/workload-query.json).

## Compatibility and limitations

Generated suites and their reports retain version 1. Cookie security execution
requires alpha.6 or later; regenerate older suites containing stored
unsupported-authentication blockers, including cookie authentication. Execution remains explicitly
selected GET/HEAD only. Cookie values are static snapshots: there is no login,
cookie jar, response-cookie adoption, token renewal or automatic retry. Direct
benchmark commands still have no custom-header or session-cookie bindings.

Authored plans retain `workload_version: 1` and reports retain `schema_version: 2`.
Existing plans without `query` keep their behavior. Earlier binaries reject the
new field, including an empty array. Queries support at most 32 string pairs,
128 UTF-8 bytes per name, 4096 bytes per value and 8192 encoded bytes in total.
There is no variable interpolation, response extraction, automatic pagination
or cursor walking. Plan files contain literal query data; keep private plans
private. External targets and intermediaries may log complete URLs, so query
parameters must not carry credentials.

The alpha.5 decoded-input and schema-complexity limits remain in force. They do
not impose a total process-memory limit or synchronous schema-validation
deadline. Workload writes still require explicit opt-in; the caller owns target
authorization, fixtures, service lifecycle and cleanup. No capacity guarantee
or complete security audit is claimed.

## Supported artifacts and release evidence

Supported binary targets remain Linux x86_64 built on Ubuntu 24.04 and macOS
arm64. Other platforms are unverified. macOS binaries are unsigned and not
notarized. Distribution is through GitHub prerelease archives; no crates.io
publication, hosted deployment or customer rollout is included.

Each archive includes the executable, documentation and examples, licenses,
target-specific dependency notices, Rust standard-library attribution, build
provenance and recursive internal checksums. Archive-level SHA-256 sums accompany
the release. Checksums establish byte consistency; no artifact signature is
provided.

Publication requires every [release threshold](../release-policy.md) on the final
revision: formatting, strict Clippy, all Rust/Python regressions on both supported
platforms, a fresh dependency audit, independent review, verified notices, and
built/extracted executable smokes. These checks use disposable synthetic
loopback fixtures. Historical external-service acceptance does not verify this
release's packaged binaries; no fresh Roots or customer acceptance is claimed.

The final revision, CI and artifact workflows, security findings disposition,
test counts, archive digests and public download verification are recorded in the
[GitHub release entry](https://github.com/givtaj/rusta-pitest/releases/tag/v0.1.0-alpha.6).
This source document describes the candidate and does not assert publication.
