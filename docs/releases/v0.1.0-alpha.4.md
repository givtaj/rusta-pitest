# v0.1.0-alpha.4

Authenticated fixed-arrival workloads and client-reported correctness fixes.
Prepared release date: October 28, 2026. CLI and report interfaces remain alpha.

## Included

- Author reviewed JSON workloads with named requests, isolated static actor
  cookie/custom-header bindings, and expected denial or optional JSON schema checks.
- Offer deterministic request mixes independently of response completion, with
  measured phases, reserved group capacity, bounded concurrency, no waiting queue,
  and explicit accounting for late, capacity-limited, failed, cancelled and unsent requests.
- Execute explicitly selected sequences and opted-in writes, with immutable
  environment/file body bytes and caller-supplied idempotency keys for deliberate replay.
- Run explicit setup before measurement; report scoped thresholds, request/group/phase
  latency distributions, and bounded monotonic timing evidence with wall-clock correlation.
- Save workload reports as `schema_version: 2`, `kind: workload`; existing direct,
  profile, and suite reports keep their version-1 shapes and semantics.
- Configure bounded OpenAPI contract/generated-suite/input-suite byte budgets
  from 1 byte through 64 MiB without relaxing structural/schema limits.
- Encode reserved characters in simple-style path fixtures as data. Cancel
  incomplete wizard input at EOF, including whitespace or partial final confirmation.
- Include reusable documentation and examples in binary archives, with recursive
  internal checksums and extracted example preview verification.

See [workloads](../workloads.md), the [complete example](../../examples/workload.json),
[OpenAPI suites](../openapi-suites.md), and [report definitions](../json-reports.md).

## Supported artifacts and release evidence

Linux x86_64 on Ubuntu 24.04 or a compatible glibc environment, and macOS arm64
on the selected GitHub runner. Other targets are unverified. macOS executables
are unsigned and not notarized. Distribution is through GitHub prerelease
archives; no crates.io publication is included.

Each archive contains the executable, README, contribution/security guidance,
Apache 2.0 license, documentation/examples, target-specific third-party notices,
Rust standard-library attribution, `build-info.json`, and internal `SHA256SUMS`.
The release also supplies archive-level SHA-256 sums.

Publication requires the [release policy](../release-policy.md): formatting,
strict Clippy, all discovered Rust/Python tests on both supported targets,
dependency audit, independent review, verified notices, and smoke checks of
both built and extracted release binaries. Focused artifact smokes cover the
new workload CLI, static actor isolation, denial checks, write permission/replay,
threshold failure, capture loss, byte-limit flags, and the two reported regressions.
These are functional checks against synthetic loopback fixtures, not target-service
capacity measurements or a complete security audit.
The [reviewed CodeQL record](../codeql-alpha4-review.md) records the scoped
security findings and their disposition; final candidate analysis evidence
must still be checked before publication.

Before publication, record the exact candidate SHA, successful CI/artifact and
security-analysis runs, observed test counts, archive names, and verified digests
in the [GitHub release entry](https://github.com/givtaj/rusta-pitest/releases/tag/v0.1.0-alpha.4).
This source document does not substitute for that final evidence or assert that
the release has already been published.

## Known limitations

- Authentication is a static per-actor snapshot. There is no automatic login,
  cookie update, credential acquisition, renewal, or authentication retry.
  The caller/harness owns service lifecycle, test fixtures, credentials and cleanup.
- An idempotency key is supplied by the caller and remains unchanged across all
  repetitions of its named request, including different sequences/actors. The
  server decides deduplication semantics. The runner does not claim exactly-once
  writes, rollback, or generation of a fresh logical-write key per arrival.
- Workload plans are limited to 1 MiB; bodies to 64 KiB; responses to 1 MiB.
  Further actor, phase, capacity, scheduling, schema and capture limits are
  documented. Accepted bounds are not a verified safe load or throughput guarantee.
- Oversized responses close early. Timeouts/body errors can have an observed
  status without a completed HTTP response; request lifecycle and HTTP-completion
  counters are deliberately separate. Client cancellation cannot undo server effects.
- Evidence retains only an emission-order prefix until its first budget limit.
  Dropped records are explicit, aggregate counts remain available, and interrupted
  capture is incomplete. Abrupt termination can prevent report publication.
- Direct benchmarks remain closed loop. Generated OpenAPI suites remain selected
  GET/HEAD checks executed once, with bearer/header API keys; they do not gain
  workload write permissions, negative-case semantics, or session management.
- The OpenAPI supported subset, local-only schema references, unsupported serializer
  restrictions, and lack of inferred business/dependency semantics still apply.
- Quantiles are approximate. There is no universal performance baseline or capacity
  guarantee. Source archives without Git metadata report unknown Git identity;
  official binary archives must identify the exact clean tagged revision.
