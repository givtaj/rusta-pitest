# v0.1.0-alpha.9

Authored workloads can bind typed private fixtures per actor. One workload can
send the same named read for two actors and check each response against that
actor's own case ID and expected tenant set.

## Bind and check actor fixtures

Declare `env` and `type` for each binding in `actors.<actor>.fixtures`. Set the
environment variable to a JSON value. Preview validates the declaration and
references without reading those values or sending requests. Execution resolves
the selected actors' fixtures during preflight, before setup or measured
traffic.

Use `{"fixture":"binding"}` in a structured path segment, query value, or
`expect_fields` assertion. `equals` compares the JSON value at a JSON Pointer.
`equals_set` compares an array of distinct scalar values without requiring the
same order. The response must satisfy every configured check, including any
response schema. Keep expected tenant fixtures separate from the credential
environment variable so the test can detect the wrong identity.

In the loopback example, the expected identity returns HTTP 200 and passes with
its tenant IDs in reverse order. Swapping only the credential produces another
schema-valid HTTP 200 response. The measured read fails with
`response_field_mismatch` and the command exits 1. [Run the synthetic example](../workloads.md#private-actor-fixtures)

## Compatibility and limits

- Paths and queries accept `string`, `integer`, `number`, and `boolean`
  fixtures. URL encoding applies to each resolved value once. A `number`
  fixture retains its validated numeric spelling in the URL.
- Numeric expectations, including nested values and set members, must be
  integers from `-9223372036854775808` through `18446744073709551615`.
  Fractions, exponent notation, out-of-range values, and `-0` are rejected in
  expectations. Use `0` for zero and JSON strings on both sides for larger or
  decimal IDs. Field assertions require a JSON body and are unavailable for HEAD.
- Each actor can declare up to 32 fixtures, with 8 KiB per JSON input and 64 KiB
  per actor. Each request can declare up to 32 assertions. Sets are limited to
  256 scalar values. Reports and diagnostics omit private fixture values and
  environment-variable names. The target may log resolved request URLs.
- Literal path strings and literal query values retain their behavior. Earlier
  binaries reject the new fixture syntax. Plans still use `workload_version: 1`
  and authored workload reports use `kind: workload` and `schema_version: 2`.
  Capacity plans use `actor.fixtures` for the single actor. Capacity reports
  retain `kind: workload_capacity` and `schema_version: 1`.

## Release verification

The supported binaries are Linux x86_64 on Ubuntu 24.04 or a compatible glibc
environment, and macOS arm64. The macOS binary is unsigned. The release checks
exercise built and extracted binaries with synthetic loopback actors, including
the credential-swap failure, a schema-only control, and redaction. See the
[release policy](../release-policy.md) for the required checks.

From a Git checkout of the release tag, run the smoke suite against your
extracted executable. This command uses the macOS arm64 target.

```sh
python3 scripts/release-smoke.py /path/to/extracted/rusta-pitest \
  --expected-version 0.1.0-alpha.9 --expected-revision "$(git rev-parse HEAD)" \
  --expected-target aarch64-apple-darwin --require-clean
```

Use `x86_64-unknown-linux-gnu` for the Linux x86_64 archive.
