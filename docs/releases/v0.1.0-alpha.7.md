# v0.1.0-alpha.7

This candidate was prepared on November 18, 2026. It corrects two ways an
OpenAPI suite could pass unexpectedly, preserves reports when a pipe closes,
and fixes how authored workloads measure time and admit new requests.

## OpenAPI suites

- A `--fixture` name must match a parameter's `fixture` slot in the suite.
  Preview and execution reject a typo before sending requests. If an earlier
  run used a generated value, correct the spelling against the generated suite
  and run it again. Bindings for declared slots on unselected operations are
  still accepted.
- String response headers are validated as received, including quotes and
  backslashes. For a header that must equal `staging`, the wire value
  `"staging"` now fails with `response_header_mismatch`. If quotes are part of
  the contract, include them in the expected string. Numeric and boolean
  header schemas continue to check typed values.

## Saved reports

When stdout is piped to `head`, the runner finishes the requested operations
and writes the complete report to `--output`. Its exit status reflects the
run's outcome even when the reader exits early. Choose a fresh output path for
each run so existing reports are preserved. [JSON reports](../json-reports.md)

## Authored workloads

- `elapsed_secs` now stops when the drain finishes. The completed-request rate
  (`rates.completed_per_sec`) includes time spent finishing in-flight work and
  excludes final accounting, threshold evaluation, and report generation.
  Compare completion rates across versions with this change in mind. Offered
  and started rates use the planned arrival window.
- A new arrival must start before its phase ends, even when its
  `max_start_lag_ms` allowance extends past the deadline. An arrival that misses
  the boundary is reported as `unsent` with reason `scheduler_late`. Already
  admitted sequences can finish during the drain.

Generated suites and suite reports use version 1. Authored workload plans use
version 1 and workload reports use schema version 2. [Workload metrics and
scheduling](../workloads.md)

## Quickstart

Run the [README quickstart](../../README.md#openapi-contract-suites) from the
repository root. It generates a suite from `examples/widgets.openapi.yaml` in
a fresh temporary directory, then previews `getWidget` and `createWidget`
without sending API requests.

## Release verification

The supported binary targets are Linux x86_64 on Ubuntu 24.04 or a compatible
glibc environment, and macOS arm64. The macOS binary is unsigned. Publication
requires checks on the final tagged revision, verified dependency notices and
checksums, and smoke tests of the extracted archives on both targets.
See the [release policy](../release-policy.md) for the full criteria.
